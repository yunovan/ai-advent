# Архитектура проекта AI Advent

AI Advent — учебный проект на **Java 21** и **Spring Boot 4** (Gradle, Kotlin DSL),
в котором каждый день курса живёт в отдельном пакете `com.yunovan.aiadvent.dayNN`.
Пакеты дней изолированы: у каждого свой `*Properties`-record, сервис, контроллер,
CLI-раннер и страница `static/dayNN.html`.

## Общая структура

- `com.yunovan.aiadvent` — корень приложения (`AiAdventApplication`).
- `day01` … `day31` — по одной папке на день; номер дня определяет CLI-флаг `--day=NN`.
- `llm` — клиент облачной LLM (`LlmClient`, `LlmProperties`, `CompletionCommand`, `LlmReply`).
- `agent` и `agent.dialog` — базовый чат-агент и диалоговая память (дни 6–12).

Точка входа — `AiAdventApplication`; все `*Properties` регистрируются через
`@EnableConfigurationProperties`. Spring-сервер по умолчанию слушает порт `8080`.

## Дни и назначение

- **Дни 1–5** — первые запросы к облачной LLM, форматы ответа, сравнение моделей.
- **Дни 6–12** — агент, неограниченный контекст, учёт токенов, сжатие и слои памяти.
- **Дни 13–15** — управляемые переходы и инварианты диалогов.
- **Дни 16–21** — MCP: MCP-серверы и клиенты, композиция, планировщик, индекс документов.
- **Дни 22–25** — RAG: контрольные вопросы, переранжирование, цитаты и антигаллюцинации, чат с памятью.
- **День 26** — локальная LLM через Ollama (`qwen2.5:3b`), `Day26LocalLlmClient`.
- **День 27** — локальный ассистент (чат без облака).
- **День 28** — полностью локальный RAG (`Day28RagService`) + сравнение с облаком.
- **День 29** — оптимизация локальной LLM (два профиля: baseline и tuned).
- **День 30** — локальная LLM как приватный HTTP-сервис.
- **День 31** — ассистент разработчика: RAG по документации проекта + MCP-инструменты git.

## Слои RAG

1. **Корпус** — документы читает загрузчик (`Day21CorpusLoader` для дня 21,
   `Day31ProjectIndex` для дня 31).
2. **Чанкинг** — стратегии `fixed` (окно ~600 символов с перекрытием) и
   `structural` (по заголовкам/параграфам); классы `Day21FixedChunker`,
   `Day21StructuralChunker`.
3. **Эмбеддинги** — `Day21EmbeddingService`: локальные n-граммовые (feature hashing)
   векторы размерности 512, без сети.
4. **Индекс** — `Day21IndexStore` сохраняет JSON (`data/day21-index/index-*.json`).
5. **Поиск** — косинусная близость + BM25-переранжирование (`Day23ReRanker`).
6. **Генерация** — локальная LLM отвечает строго по найденному контексту.

## Локальная LLM

Локальная модель — Ollama `qwen2.5:3b` (Q4_K_M, ~1990 МБ в памяти, контекст 32768).
Клиент `Day26LocalLlmClient` работает с нативным API Ollama: `POST /api/chat`,
`GET /api/version`, `GET /api/tags`, `GET /api/ps` (загруженная модель),
`POST /api/show` (квантование, параметры, контекст). Параметры генерации задаёт
`Day26ChatOptions` (temperature, max_tokens, num_ctx).
