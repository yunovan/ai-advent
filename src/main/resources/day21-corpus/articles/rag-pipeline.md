# Пайплайн RAG: от документа к ответу

RAG (Retrieval-Augmented Generation) — архитектура, в которой модель сначала
находит релевантные фрагменты из внешнего источника, а затем отвечает, опираясь
на них. Правильный ответ рождается из найденного контекста, а не из памяти
модели. Пайплайн собирается из трёх фаз: индексация, поиск, генерация.

## Фаза индексации

Сначала корпус документов превращается в индекс. Документы читаются из их
естественных форматов: markdown, обычный текст, исходный код, PDF. Каждый
документ проходит следующие шаги:

- извлечение текста и метаданных — источник (путь файла), заголовок, количество
  символов;
- чанкинг по выбранной стратегии (см. «Чанкинг документов»): фиксированный размер
  или по структуре документа;
- вычисление эмбеддинга каждого чанка;
- сохранение чанков вместе с векторами и метаданными в хранилище индекса — в этом
  проекте это JSON-файл на диске.

Результат фазы — самодостаточный файл: для поиска по индексу не нужен ни исходный
корпус, ни сеть. Индекс можно сохранить, загрузить и обновить по мере изменения
документов.

## Фаза поиска

Поиск стартует с запроса пользователя. Запрос превращается в эмбеддинг теми же
функциями, что применялись к чанкам, — так векторы сравнимы. Затем индекс
перебирает все чанки, считает косинусную близость между вектором запроса и
вектором каждого чанка и сортирует результаты. В ответ возвращается топ-k чанков
со скорами, источники и секции.

Качество поиска зависит от двух вещей: как нарезан корпус и как считаются
эмбеддинги. Обе вещи проверяются пробами: на корпусе заранее известен список
вопросов с правильными фрагментами, и успех фазы — это попадание правильного
фрагмента в топ.

## Фаза генерации

Финальный слой — генеративная модель. Она получает найденные чанки как контекст
и формулирует ответ на естественном языке. Правила генерации: опираться только на
контекст, ссылаться на источник, не выдумывать факты. Если LLM недоступна,
ответом становится аккуратно оформленный результат поиска — сырой, но честный.

## Где живёт индекс в проекте

Индекс документов этого дня — локальный JSON-индекс без сети и без внешних
зависимостей: эмбеддинги детерминированные, хранилище — файл `index-<стратегия>.json`.
Каждый чанк несёт метаданные: source, title, section, chunk_id, позицию в тексте
и количество символов. Один и тот же корпус индексируется двумя стратегиями
чанкинга, и метрики на пробных запросах показывают, какая из них точнее.
